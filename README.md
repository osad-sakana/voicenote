# voicenote

ローカルで音声を録音し、faster-whisperで文字起こしを行い、Markdownノートとして保存するPythonツールです (Obsidianなどのノートツールと互換)。

## 必要要件

- Python 3.10以上
- [uv](https://github.com/astral-sh/uv)（Pythonパッケージマネージャー）

## インストール

1. uvをインストールしていない場合は、まずインストールします:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

2. 依存関係をインストールします:

```bash
uv sync
```

### グローバルインストール（オプション）

`uv tool`を使うと、システム全体で`voicenote`コマンドとして使用できます:

```bash
uv tool install . --python 3.12
```

> Python 3.14以降では依存関係がサポートされていないため、3.12または3.13を指定してください。

インストール後は、どこからでも実行可能です:

```bash
voicenote           # 録音開始
voicenote --config  # 設定変更
```

アンインストールする場合:

```bash
uv tool uninstall voicenote
```

## 使い方

### 初回実行

初回実行時は設定を対話的に入力します:

```bash
uv run main.py
```

> `uv run` は実行前に自動的に依存関係を同期します。

以下の項目を入力します:
- ノート保存フォルダの絶対パス（Obsidian Vault内などお好みの場所）
- 文字起こしモード（local: faster-whisper / openai: Whisper API）
- 使用するWhisperモデル（tiny, base, small, medium, large-v3）
- テキスト整形モード（none / rule / llm）

### 2回目以降

設定が保存されているので、すぐに録音が開始されます:

```bash
uv run main.py
```

録音中に `Ctrl+C` を押すと録音が終了し、文字起こしが開始されます。

### 設定の再入力

設定を変更したい場合は `--config` オプションを使用します:

```bash
uv run main.py --config
```

### ライブ文字起こし（`--live`）

録音しながらローカルでリアルタイムに文字起こしし、ローカルLLMで要約を更新します（通信はすべて自マシン内で完結）。

```bash
uv sync --extra live-mlx    # 任意: Apple Silicon で MLX エンジンを使う場合
ollama serve                # 任意: 要約用のローカルLLMサーバー
ollama pull qwen2.5:7b      # 既定の要約モデル

uv run main_cli.py --live
```

- `Ctrl+C` で終了すると、録音WAV（デスクトップ）と `YYYY-MM-DD_HHMMSS_live.md`（要約+タイムスタンプ付き文字起こし）が保存されます。ノート名の時刻は録音WAVの開始時刻と同じです（同名があれば `_2`, `_3`, ...）
- 終了後の要約作成中にもう一度 `Ctrl+C` を押すと、ライブノートを作らずに終了します（WAVは保存済み）
- ライブのテキストは速報版です。高精度な全文は `uv run main_cli.py --file <WAVのパス>` で再文字起こししてください。`--config` で OpenAI 文字起こし / LLM 整形を選んでいる場合、この再文字起こしは音声・本文を OpenAI に送信します
- Ollama が起動していない・モデルが無い場合は要約なしで続行します。MLX が使えない環境では faster-whisper で動作します
- エンジン・モデル・VAD（音声区間検出）・言語・要約モデル・接続先は `--config` の「ライブ文字起こし設定」で変更できます
- VAD の既定は `silero` です。マイク入力が小さい環境では `energy`（音量しきい値方式）は発話を取りこぼしやすく、実測では発話の約7割を検出できませんでした。Silero VAD を読み込めない場合は警告を表示して `energy` で続行します
- **推奨設定（Apple Silicon）**: `uv sync --extra live-mlx` を実行し、`--config` のライブ文字起こし設定でエンジン `mlx` とモデル `large-v3-turbo`（mlx 選択時の既定値）を選んでください。small より明確に高精度で、区間あたりの遅延は中央値で約1.5秒です（M1 16GB 実測。音声が崩れた区間では10秒前後かかることがあります）。MLX が使えない環境では自動で faster-whisper + `small` に切り替わります（faster-whisper の CPU 実行では large-v3-turbo は遅すぎて実時間に追いつきません）
- マイクの入力レベルが低いと認識精度が大きく落ちます。OS のサウンド設定で入力音量を上げてください

### GUI でのライブ文字起こし

`uv run main.py` で起動した GUI でも、ライブ文字起こしを使えます。

1. **準備（任意）**: 要約を使う場合はローカルLLMを用意します。Apple Silicon では MLX エンジンも入れておくと高精度です

   ```bash
   ollama serve             # 要約用のローカルLLMサーバー
   ollama pull qwen2.5:7b   # 既定の要約モデル
   uv sync --extra live-mlx # 任意: Apple Silicon で MLX エンジンを使う場合
   ```

2. **設定**: 「設定」の「ライブ」タブで、エンジン・モデル・VAD・言語・要約モデル・接続先を選びます。ライブノートは「文字起こし保存フォルダ」に保存されるので、先に設定してください
3. **開始**: 上部のモード選択で「ライブ」を選び、入力デバイスを選んで「ライブ開始」を押します。ライブモードではウィンドウが広がり（760x800）、サイズを変えられます（最小 600x790）。画面の縦が 940pt 未満（メニューバー・ドック分の見積り 140pt を引くと 800 が入らない画面。例: 13インチ標準の 1440x900 では 760）のときは、高さと最小の高さを画面に合わせて縮め、メモ欄を2行・上限案内を1行に省略し・間隔を詰めて要約欄を優先します
   - 初回はモデルを自動でダウンロードします（進捗バーを表示。large-v3-turbo は 1GB 以上あります）。ダウンロード中に「停止」を押すと、ダウンロードが終わったところで開始を取り消します
   - Ollama が起動していない・モデルが無い場合は、案内を表示して要約なしで続行します。MLX が使えない環境では faster-whisper に切り替わります
4. **録音中**: 要約を大きく表示し、その下に速報の文字起こしを数行だけ表示します。文字起こし欄は要約欄の右上の「文字起こしを隠す」で折りたためます（折りたたむと要約欄が広がります。「文字起こしを表示」で戻ります）。要約欄は3行分以上の高さを保ちます。ただし縦が約900pt未満の画面では、案内バナー・入力レベル警告・上限案内・完了表示が同時に出る重い状態で3行を割ることがあります（実測の要る窓の高さ: バナー1件で 741、3件で 758。画面の縦に直すと約 881pt / 898pt）。大きい画面でも、窓を最小の高さ（790）近くまで縮めた状態でバナーが3件同時に出ると、数px（790 で 9px）割ります。案内・警告・完了表示などでウィンドウの高さが足りなくなると、文字起こし欄が自動で折りたたまれ、ボタンが「文字起こしを表示（狭いため自動で非表示）」になります。押すと、要約欄の3行分を保ったまま文字起こし欄の見出しと1行分以上が入るなら表示し直します（文字起こし欄は下から削られ、窓を広げると自動の折りたたみに戻ります）。1行も入らないときは表示せず、ボタンが「狭いため文字起こしを表示できません。ウィンドウを広げてください」になります（詳細ログにも「警告:」として1回残ります）。下の行に入力レベル、文字起こしの遅れ（「遅延 X秒」）、処理しきれず捨てた音声チャンク数（「破棄 N」）が出ます
   - 入力レベルが低いと案内が出ます。認識精度が大きく落ちるので、OS のサウンド設定で入力音量を上げてください
5. **停止**: 「停止」を押すと、まず録音WAVを確定し（録音フォルダ。既定はデスクトップ）、残りの区間の文字起こしと最終要約を作ってから `YYYY-MM-DD_HHMMSS_live.md` を保存します。待ちきれない場合は「中断して保存」で、ここまでの内容だけのノートを保存できます（WAVは保存済み）
6. **完了後**: WAV とノートの保存先が表示されます。「高精度で文字起こし」を押すと「文字起こしだけする」モードに切り替わり、WAV のパスが入力された状態になるので、そのまま「文字起こし開始」で高精度な全文を作れます

#### 参加者・メモ（要約の参考情報）

ライブ画面の上部に「参加者」と「メモ」の入力欄があります（ライブモードのときだけ表示）。

- **参加者**: 名前を読点「、」またはカンマ「,」で区切って入力します（例: `田中、佐藤、鈴木`）。要約で名前の表記ゆれを揃える参考にします
- **メモ**: 議題・用語・固有名詞など、要約の参考にしたい内容を自由に書きます
- ライブの開始前でも、録音中・停止後の処理中でも編集できます。編集した内容は**次回の要約から**反映されます（編集しただけでは要約は作り直されません）。「ライブ開始」「停止」「中断して保存」を押した時点と、アプリを閉じる時点の入力内容は、反映待ちのものも含めて必ず使われます
- 参加者・メモはライブノートの「参加者」「メモ」の節（参加者は frontmatter の `participants` にも）に保存されます。停止後の処理中に編集した内容も、保存時点のものがノートに入ります
- 要約はローカルLLMで作るので、参加者・メモが外部に送信されることはありません。ログにも本文は出力しません
- メモは参考情報としてだけ扱います。メモに書かれた指示（「〜と出力して」など）は命令として扱わないよう、要約のLLMに指示しています
- 上限: 参加者は30人（1人40文字）まで、メモは2000文字までです。超えた場合は入力欄の下に案内が出て、先頭の分だけを使います
- ライブが終わっても入力内容は残ります（同じ会議の続きをそのまま再開できます。アプリを閉じると消えます）。新しい会議では「クリア」で消してください（ライブ中でもクリアできます）

ライブ実行中（停止後の処理中を含む）は、他のモードの録音・文字起こしは開始できません（逆に、通常の録音・文字起こし中はライブを開始できません）。

## 出力形式

文字起こし結果は以下の形式でMarkdownノートとして保存されます:

```markdown
---
created: 2026-01-16T12:34:56.789012
type: transcription
tags:
  - recording
  - raw
---

# 録音文字起こし

[文字起こし結果]
```

ファイル名: `YYYY-MM-DD_HHMMSS_raw.md`

```
├── recorder.py          # 録音機能モジュール
├── transcriber.py       # 文字起こし機能モジュール
├── formatter.py         # テキスト整形モジュール
├── note_writer.py       # Markdownノート保存モジュール
├── gui/                 # GUI 関連 (App, SettingsDialog, etc.)
├── tests/               # ユニットテスト
├── pyproject.toml       # プロジェクト設定・依存関係
└── README.md
```

## 機能

- ✅ ローカルで完結（外部APIを使用しない）
- ✅ 対話的な設定管理
- ✅ リアルタイム録音
- ✅ faster-whisperによる高精度な文字起こし
- ✅ Markdownノートとしての自動保存（YAMLフロントマター付き、Obsidian互換）
- ✅ Richライブラリによる美しいUI
- ✅ モジュール化された綺麗なコード構造
